# Yandex Market Sales Boost Automation

## Самый простой запуск

> В версии 1.3.1 `START_HERE.bat` открывает чистое интерактивное меню. Во время долгих операций BoostCtl выводит текущий этап работы, чтобы пользователь видел, что процесс продолжается.


Если вы впервые открыли BoostCtl, запустите:

```text
START_HERE.bat
```

Откроется меню со всеми основными действиями.

### Как подготовить список товаров

Откройте:

```text
data\campaigns_input.txt
```

и вставьте строки:

```text
2020488/1#1;5
20210026/9#1;7.5
2529892/9П-7,5#1;10
```

Формат:

```text
SKU;СТАВКА
```

После этого в `START_HERE.bat` выберите **«Создать campaigns.json»**.

Можно также скопировать две колонки `SKU` и `ставка` непосредственно из Excel — генератор понимает разделитель TAB.

Генератор:
- проверяет ставки;
- не допускает повторов SKU;
- создаёт корректный `data\campaigns.json`;
- не записывает файл, если во входных данных есть ошибка.

Рекомендуемый порядок для нового пользователя:

```text
1. Установить зависимости
2. Создать campaigns.json
3. Проверить campaigns.json
4. Выполнить предварительную проверку Яндекса
5. Создать одну тестовую кампанию
6. Только после проверки — массовый запуск
```


Создаёт отдельную кампанию **«Буст продаж»** для каждого SKU в кабинете Яндекс Маркета.

Рабочая схема:

```text
видимый SKU
    ↓
resolveOffersForModels
    ↓
внутренний offerId (dcmp-...)
    ↓
resolvePutSalesCampaign
    ↓
отдельная кампания
```

## Возможности

- одна кампания на один SKU;
- название `SKU | ДД.ММ.ГГГГ`;
- текущая дата берётся из Windows автоматически;
- точное сопоставление `article == SKU`;
- кэш внутренних `offerId`;
- режим проверки без создания кампаний;
- повтор только ошибочных строк;
- CSV-отчёт и текстовые логи;
- повторные HTTP-попытки при временных ошибках;
- сохранение браузерной сессии локально.

## Быстрый запуск на Windows

1. Установите Python 3.11+.
2. Запустите:

```text
00_INSTALL.bat
```

3. Заполните `data/campaigns.json`.
4. Проверьте файл:

```text
01_VALIDATE.bat
```

5. Выполните безопасную проверку без создания:

```text
02_DRY_RUN.bat
```

6. Создайте одну тестовую кампанию:

```text
03_TEST_ONE.bat
```

7. Запустите весь список:

```text
04_RUN_ALL.bat
```

Ошибочные строки можно повторить через:

```text
05_RETRY_ERRORS.bat
```

## Командная строка

После `00_INSTALL.bat` доступна команда:

```bash
yandex-boost validate
yandex-boost run --dry-run
yandex-boost test
yandex-boost run
yandex-boost retry-errors
```

Дополнительные параметры:

```bash
yandex-boost run --date 05.08.2026
yandex-boost run --start 10 --limit 20
yandex-boost run --no-cache
yandex-boost run --verbose
```

## Результаты

- `reports/api_report.csv` — результат каждой строки;
- `logs/YYYY-MM-DD.log` — подробный журнал;
- `data/offer_cache.json` — кэш соответствий SKU → `dcmp-offerId`;
- `browser_profile/` — локальная сессия браузера.

Эти файлы исключены из Git через `.gitignore`.

## Безопасность

Никогда не публикуйте:

- `browser_profile/`;
- cookies и `Session_id`;
- заголовок `sk`;
- HAR-файлы;
- реальный `data/campaigns.json`, если SKU являются внутренними данными.

Скрипт не сохраняет cookie или `sk` в исходники: токен считывается из текущей авторизованной браузерной сессии.

## Важное ограничение

Используются внутренние HTTP-запросы веб-интерфейса Яндекс Маркета. Яндекс может изменить их без предварительного уведомления. Перед массовым запуском после изменений кабинета выполняйте `02_DRY_RUN.bat` и `03_TEST_ONE.bat`.

## Удаление кампаний

Удаление работает только по явному списку `campaign_id` из локального файла:

```text
data/campaigns_to_delete.json
```

Сначала обязательно выполните:

```text
07_DELETE_PREVIEW.bat
```

Этот режим ничего не удаляет и показывает все найденные кампании.

Для фактического удаления:

```text
08_DELETE_CAMPAIGNS.bat
```

Программа потребует точное подтверждение вида `DELETE 25`. Если хотя бы один ID из файла не найден, массовое удаление не запускается. После операции автоматически обновляется `reports/campaigns_from_yandex.csv` и создаётся `reports/delete_report.csv`.
