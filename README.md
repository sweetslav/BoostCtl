# BoostCtl

**BoostCtl** — утилита для массового создания отдельных кампаний «Буст продаж» в Яндекс Маркете.

Каждый SKU получает отдельную кампанию, поэтому статистику можно анализировать на уровне конкретного товара.

## Что изменилось в 1.1.0

Главное изменение — **защита от повторного создания кампаний для одного SKU**.

Перед запуском BoostCtl теперь:

1. открывает фактический список кампаний в Яндекс Маркете;
2. собирает их ID и названия;
3. извлекает SKU из названий вида `SKU | ДД.ММ.ГГГГ`;
4. строит множество уже используемых SKU;
5. сравнивает его с `campaigns.json`;
6. уже существующие SKU помечает как `SKIP`;
7. создаёт только новые кампании.

Дата в названии больше не позволяет случайно создать дубль того же SKU.

Также программа показывает перед запуском:

```text
Входных SKU: 100
Уникальных SKU в текущих кампаниях Яндекса: 134
SKU-дублей уже в Яндексе: 26
Уже существуют и будут пропущены: 17
Будут созданы: 83
```

## Как работает создание

```text
SKU
 ↓
проверка существующих кампаний
 ↓
SKU уже есть? ── да ──> SKIP
 ↓ нет
resolveOffersForModels
 ↓
offerId вида dcmp-...
 ↓
resolvePutSalesCampaign
 ↓
кампания создана
```

## Входной файл

Рабочий файл: `data/campaigns.json`.

```json
[
  {
    "sku": "20210026/9#1",
    "bid": 5
  },
  {
    "sku": "21211538/9#1",
    "bid": 5
  }
]
```

Повтор одного SKU внутри файла запрещён: `validate` завершится ошибкой до создания кампаний.

## Быстрый запуск на Windows

Первичная установка:

```text
00_INSTALL.bat
```

Проверка структуры `campaigns.json`:

```text
01_VALIDATE.bat
```

Проверка против фактических кампаний Яндекса без создания:

```text
02_PREFLIGHT.bat
```

Проверка API без создания кампаний:

```text
02_DRY_RUN.bat
```

Создание одной новой кампании:

```text
03_TEST_ONE.bat
```

Массовое создание:

```text
04_RUN_ALL.bat
```

Повтор строк, завершившихся ошибкой:

```text
05_RETRY_ERRORS.bat
```

Выгрузка текущих кампаний:

```text
06_EXPORT_CAMPAIGNS.bat
```

Результат сохраняется в:

```text
reports/campaigns_from_yandex.csv
```

Колонки:

- `campaign_id`;
- `campaign_name`;
- `sku`;
- `url`.

## Командная строка

После установки пакет доступен как `boostctl`:

```bash
boostctl validate
boostctl preflight
boostctl test
boostctl run
boostctl retry-errors
boostctl export
```

Можно использовать параметры:

```bash
boostctl run --date 07.08.2026
boostctl run --start 20 --limit 50
boostctl run --dry-run
boostctl run --no-cache
```

Если `--date` не указан, используется текущая локальная дата компьютера.

## Отчёты

`reports/api_report.csv` содержит результат обработки каждого SKU.

Основные статусы:

- `CREATED` — кампания создана;
- `SKIPPED_EXISTS` — SKU уже существует в кампаниях Яндекса;
- `VALID` — SKU успешно проверен в режиме без создания;
- `ERROR` — ошибка поиска товара или создания кампании.

`reports/campaigns_from_yandex.csv` — фактический снимок кампаний на момент запуска.

## Кэш offerId

После успешного поиска внутренний `offerId` сохраняется локально в:

```text
data/offer_cache.json
```

Кэш ускоряет повторные запуски. Для принудительного повторного поиска:

```bash
boostctl run --no-cache
```

## Безопасность

В Git не должны попадать:

- `browser_profile/`;
- cookies и `Session_id`;
- заголовок `sk`;
- HAR-файлы;
- `data/campaigns.json`;
- `data/offer_cache.json`;
- отчёты и логи.

Они уже добавлены в `.gitignore`.

## Ограничение защиты от дублей

SKU извлекается из названия кампании формата:

```text
SKU | ДД.ММ.ГГГГ
```

Поэтому автоматическая защита гарантированно работает для кампаний, созданных BoostCtl и предыдущими версиями нашего скрипта. Кампании с произвольными ручными названиями экспортируются, но SKU из их названия определить нельзя.

## Технологии

- Python 3.11+
- Playwright
- внутренние HTTP-запросы веб-интерфейса Яндекс Маркета

## Важно

BoostCtl использует внутренние запросы веб-интерфейса Яндекс Маркета. Они могут измениться без предварительного уведомления. После значительных изменений кабинета рекомендуется сначала запускать `preflight` и `test`.
